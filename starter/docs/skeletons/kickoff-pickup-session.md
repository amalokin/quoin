# Pickup session — ‹the handoff›

## Launch

This is an implementation-class session, the class that picks up a handoff's results, launched with `claude --model ‹the implementation class's model, process.md §Model policy, the binding table› --effort max`, the owner confirming `/effort` reads max; if the work asked of you belongs to the planning class, say so before you start (process.md §Model policy).

## The results

Resume from the results doc, ‹docs/handoffs/name-results.md›, and the roadmap, not from the old session's transcript (process.md §Handoff economics, step 3).

## Checks first

Before resuming from the results, check that the handoff and the results doc are committed on the branch you read them from and that the results doc names the handoff's execution SHA (process.md §Handoff economics, step 3).

## Ruling from the results

If the handoff was a guided live session, its guide interpreted nothing: if this session owns the question, rule from the results yourself, and call counsel when a counsel trigger fires (process.md §Handoff economics, a guided live session; §Model policy, Counsel triggers).

## The work the results feed

Then do the work the results feed, ‹the plan's next task or the item in flight›; when they feed an item in flight this is an implementation session, so its plan check, ledger, seats and counsel triggers apply (process.md §Handoff economics, step 3; §II, Implementation session).
